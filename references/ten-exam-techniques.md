# AI Coding 笔试十条通用技巧

以下内容根据截图、公开题解和题型指南蒸馏，不是对截图轮播中十张图片的逐字转录。

## 1. README 是唯一题面真相

先读环境、契约、规则、交付物和加分项。常识、框架默认行为和模型建议都不能覆盖题面原文。

## 2. 先锁契约，再让模型写代码

将入口、端口、路径、字段、枚举、状态码、退出码、精度和时间边界逐字写进 `spec.md`。弱模型最容易因为“优化命名”批量丢分。

## 3. 用 SDD 固定上下文

至少保留 `spec.md`、`design.md`、`tasks.md`。每轮实现前都从对应规范取约束，防止长对话中的目标漂移。

## 4. 按可验收功能块推进

不要按数据层、服务层、接口层横向铺开。优先完成一条可以立刻运行测试的纵向主链，再扩展旁支。

## 5. 第一轮只做最小闭环

先达到“能启动、能调用、主链能走通”。复杂 UI、高并发、生产级认证和无关抽象后置。粗糙但完整通常优于精致但残缺。

## 6. 提交前让模型先造测试攻击代码

明确说“现在只写测试，先不要改我的业务代码”。让模型从需求逐条枚举正常、非法、边界、重复、终态和失败无副作用场景，相当于提前模拟一轮隐藏评测。

## 7. 用完整失败输出纠偏

提供测试命令、完整日志、相关需求和最小修改边界。强调“已经通过的逻辑不要动”，修复后依次跑失败测试、相关边界测试和全量回归。

## 8. 对响应和输出结构逐字写死

业务逻辑正确不代表评测能读取结果。JSON 字段名、类型、层级、空数组/空值、状态码、stdout/stderr 和文件名都必须与题面一致。

## 9. 按比例预留验收时间

建议约 20% 时间审题与建模，55% 实现主链和高价值分支，25% 造用例、修复、回归和交付审计。落后时砍加分项，不砍核心测试。

## 10. 保存稳定版本，三轮不进展就换上下文

每个全绿里程碑建立 checkpoint。同一问题连续三轮没有新证据时，保留稳定版本，用需求、复现命令和完整报错建立干净会话。结果变差时回滚，不要在坏版本上继续扩大补丁。

## 一句话闭环

```text
锁定契约 -> SDD 拆解 -> 最小主链 -> 测试攻击 -> 最小纠错
-> 全量回归 -> 稳定 checkpoint -> 提交前审计
```
