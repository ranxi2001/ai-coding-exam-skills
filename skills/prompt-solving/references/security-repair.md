# 蚂蚁 AI Coding 安全审计案例参考

## 背景

题目要求根据 README 需求文档，从零构建一个 AI 代码质量审查系统，使用 mock AI 代替真实 LLM。

系统需要支持：

- 扫描单个文件或目录
- 扫描 `.py` 文件
- 输出包含行号和修复建议的详细报告
- YAML 配置
- 忽略目录
- 按 README 示例提供测试用例并通过验收

## 推荐解题路径

1. 通过审计报告定位使用 `pickle.load` 或 `exec` 的危险代码行，确认其是否接收不可信的外部输入。
2. 将不安全的 `pickle` 替换为安全的 `json` 模块，或使用 `yaml.safe_load`。若业务必须使用 `pickle`，通过白名单机制严格限制可反序列化的类。
3. 修改代码后，使用恶意构造的序列化数据进行测试，确认无法执行任意代码，同时验证业务逻辑正常运行。
4. 最后运行安全扫描和完整测试，确认漏洞已经消除且没有引入回归。

## 可抽象为通用 Skill 的能力

- 先读 README 和现有审计报告，再修改代码
- 优先定位高风险输入边界和危险 API
- 修复后必须用攻击样例验证安全性
- 同时验证安全目标、原有业务行为和验收标准
- 交付时汇总修改文件、测试结果和剩余风险

## 典型规则清单

- 硬编码密钥
- SQL 注入
- XSS
- 不安全反序列化
- Shell 注入
- 裸 `except`
- 调试模式

规则引擎可以通过正则表达式或 AST 模式实现；配置解析器、文件扫描器、规则引擎、报告生成器应保持模块化。

## 非官方经验材料

以下内容是个人复盘和求职经验，不代表任何公司正式评分标准：有人反馈秋招 AI Coding 难度上升、需要在约两小时内根据 README 完成系统开发；也有人反馈使用清晰的安全修复流程可以取得较高分数。项目实现时应将其作为训练场景，而不是考试承诺。
